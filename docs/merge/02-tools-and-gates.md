## 1. `tools/gen_sources.py`（74 行）—— 源清单单一来源

### 1.1 它生成什么

产物固定是 `cmake/core_sources.cmake`（`:45` 默认 `--output`），格式是**三段式 + 每行一个带引号的 POSIX 相对路径**（`render()` `:29-39`）：

```cmake
# Generated by tools/gen_sources.py -- do not edit by hand.
# Re-run: python tools/gen_sources.py
set(AUTOREMESHER_CORE_MODULE_SOURCES
    "src/core/base/csr.cpp"
    "src/core/base/positionkey.cpp"
    "src/core/geom/meshseparator.cpp"
    "src/core/geom/surfacemesh.cpp"
    "src/core/numeric/constrainedleastsquares.cpp"
    "src/core/numeric/mixedintegerleastsquares.cpp"
    "src/core/field/framefield.cpp"
    "src/core/field/singularitysimplifier.cpp"
    "src/core/cover/quadparameterizer.cpp"
    "src/core/param/parameterizer.cpp"
    "src/core/extract/quadextractor.cpp"
    "src/core/pipeline/autoremesher.cpp"
    "src/core/pipeline/isotropicremesher.cpp"
)
```
（上面是 `git show 0ba6c98d:cmake/core_sources.cmake` 的**原文**，13 个 `.cpp`。）

关键实现点：

- **排序键是模块序，不是字母序**：`collect()` `:19` 外层按 `MODULE_ORDER`（`:14` = `base, geom, numeric, field, cover, param, extract, pipeline`），内层 `sorted(os.listdir(...))`（`:23`）。所以**文件在模块之间移动就会改生成顺序**，`--check` 立刻变红——这是特性不是 bug。
- **路径是程序中拼字符串写死的** `:25`：`"src/core/%s/%s" % (module, name)`，含正斜杠、含 `src/core/` 前缀、含模块名。**这是唯一一处对布局的硬编码**。
- 只看 `.cpp`（`:24`），头文件不进清单（头由 include 引入）。
- 空结果直接 exit 2（`:51-53` `"no sources found under src/core"`），这是"我找不到目录结构"和"清单不一致"的区分点。

### 1.2 `--check` 语义（4 个出口，实测复核）

`:56-65` 是全部逻辑：

| 情形 | 输出 | 退出码 | 实测 |
|---|---|---|---|
| 生成物不存在 | `missing <path>` | 1 | ✅ `missing C:\...\gs2\cmake/core_sources.cmake` → `exit=1` |
| 生成物存在但内容不等 | `out of date: <path>` | 1 | ✅ 加一个 `base/c.cpp` 后 → `out of date: ...` → `exit=1` |
| 一致 | `up to date: N sources` | 0 | ✅ arch 树 → `up to date: 13 sources` → `exit=0` |
| `src/core` 下没有任何 `.cpp` | `no sources found under src/core`（stderr） | 2 | ✅ 真实 master 树 → `exit=2` |

比较方式是最严格的**全文逐字符相等**（`:61` `handle.read() != text`），写盘用 `newline="\n"`（`:67`）——**在 Windows 上也不会写成 CRLF**，所以 git 侧的 `text=auto` 不会制造假红。这条设计值得保留。

### 1.3 直接搬到 master 布局需要改什么

先给实测：`python tools/gen_sources.py --root E:/AI/autoremesher --check` → `exit=2`（stderr：`no sources found under src/core`）。也就是说**在 master 现有布局下它不是"报错"，是"该目录不存在"**。

需要改的只有三处，而且取决于合入后保留哪种布局：

| 方案 | 布局 | 改哪 | 改动量 |
|---|---|---|---|
| **A（推荐）** | 保留 arch 的 `src/core/<layer>/`（S1 已经把文件搬过去了） | **什么都不用改**。实测：把 arch 的 `src/ + include/ + cmake/` 解到 `/tmp/ar` 后 `--check` → `up to date: 13 sources` exit 0 | 0 行 |
| **B** | 保留 master 的平铺 `src/AutoRemesher/*.cpp` | ① `collect()`（`:17-26`）要加"文件名→模块"映射表 + 路径模板；② `MODULE_ORDER` 从"遍历目录的顺序"降级为"排序键"，且必须补一张 `MODULE_OF_FILE` 表（29 个文件逐个归属）；③ `render()` 头注释（`:31-32`）要改文案；④ 无人归属的文件必须报错而不是静默跳过 | ~25 行 + 一张 29 行表 |

**最小 patch 清单（函数级，方案 B 形态；方案 A 下全部不适用）**

1. `collect(root)` `:17-26`：把 `for module in MODULE_ORDER: directory = root/src/core/module` 的目录遍历，改成 `for name in sorted(os.listdir(root/src/AutoRemesher))` + 查 `MODULE_OF_FILE[name]`；路径模板 `"src/core/%s/%s"` → `"src/AutoRemesher/%s"`。
2. `MODULE_ORDER` `:14`：改成 `MODULE_OF_FILE`（`{"quadextractor.cpp": "extract", ...}`），并保留 `MODULE_ORDER` 作为**稳定排序键**，否则生成顺序会变成字母序 → 与已有产物不兼容、diff 噪音极大。
3. `main()` `:50-53`：把"空清单"的判据从 `src/core` 不存在，改成"存在未归属的 `.cpp`" → 提示补表；否则新增文件会**静默消失**（这是 GLOB 那套毛病原地复活）。
4. `render()` `:31-32`：头两行注释里的 `tools/gen_sources.py` 命令行不变，只改第二行"Re-run"提示若参数有变。

**是否要在 CMakeLists 里 include —— 必须，且必须两行**（arch 的接法是唯一的正确接法）：

```cmake
include(${CMAKE_CURRENT_SOURCE_DIR}/cmake/core_sources.cmake)      # arch CMakeLists.txt:151
set(AUTOREMESHER_CORE_SOURCES ${AUTOREMESHER_CORE_MODULE_SOURCES})  # arch CMakeLists.txt:152
```

注意**变量名不是同一个**：`gen_sources` 生成的是 `AUTOREMESHER_CORE_MODULE_SOURCES`（`:33`），`CMakeLists` 在 `:152` 把它复制成 `AUTOREMESHER_CORE_SOURCES`，然后 `:154-159` 再 `list(APPEND ...)` 五个第三方源文件，最后 `:161` `add_library(autoremesher_core STATIC ${AUTOREMESHER_CORE_SOURCES})`。**千万别以为生成物直接喂给 add_library**——中间那层 `APPEND` 是第三方源（isotropicremesher ×3 + meshoptimizer ×2）的挂载点。

对照 master 的现状：`CMakeLists.txt:43` `file(GLOB AR_CORE_SOURCES CONFIGURE_DEPENDS "src/AutoRemesher/*.cpp")`，另外 `:44-45` 还有两个 GLOB。合入时这三个 GLOB 必须**一起**处置，只换第一个会留下半套机制。

> **[S2]** 结论：`gen_sources.py` 本身与布局无关的部分（`--check` 语义、LF 写盘、空清单 exit 2）质量合格，**保留**；它不是"核心搬迁"的内容，而是"禁止 GLOB"那道闸，归 S2。若 S1 保留 `src/core` 分层（强烈建议），脚本 **0 行改动**。

### 2.3 移植到 master 后"必然失效 / 必然误报"的五处（全部有实测）

**① 布局硬耦合 → 结构性 exit 2（必然失效）**

`build_maps()` `:39` 与 `check()` `:66` 都写死 `os.path.join(root,"src","core",module)`；`:60-62` 若 `module_of_file` 为空就 `return 2`。

```
$ python /tmp/ar/tools/check_boundaries.py E:/AI/autoremesher
no modules found under src/core
exit=2
```

**这不是"报违规"，是"脚本拒绝工作"**。CI 里挂上它只有两种结果：要么立刻红（build breaker，S2 直接卡住 S1），要么被写成 `|| true`（等于没装）。 **[S1]**（必须先完成目录搬迁，这道门才有意义）

**② forwarder 解析按 basename 精确匹配 → 链式转发头必然误报**

`:52-54`：`target = os.path.basename(match.group(1))`，然后要求这个 basename **恰好等于 `src/core/<mod>/` 下的某个文件名**。arch 现状是相对路径 `#include "../../src/core/base/vector2.h"` → basename `vector2.h` → 命中（实测 arch 树 31 文件 0 违规）。

但只要 forwarder 改成**链式**（例如写成 `#include <AutoRemesher/Vector2>`，或中间再加一层），basename 变成 `Vector2`（无扩展名）→ 查不到 → 报 **`unknown forwarder`**（假违规）：

```
$ # 合成树：include/AutoRemesher/Vector2 内容为 #include <AutoRemesher/Vector2>
...\src\core\extract\a.cpp:1 unknown forwarder <AutoRemesher/Vector2>
checked 2 files, 1 violation(s)
exit=1
```

同时 master 侧有 18 个 forwarder（`git ls-tree --name-only master:include/AutoRemesher | wc -l` = 18），**全部是相对路径形态** `#include "../src/AutoRemesher/<file>.h"`（`AutoRemesher` 与 `Double` 是 `../`，其余多为 `../../`）。这类文本在搬迁后**只需机械改写前缀**（`../src/AutoRemesher/` → `../src/core/<mod>/`）就能继续命中——但有一个雷：

- `include/AutoRemesher/QuadRemesher` → `#include "../src/AutoRemesher/quadremesher.h"`，而 **master 的 `src/AutoRemesher/` 里并没有 `quadremesher.h`**（29 文件清单里没有），arch 侧直接把这个悬空转发头删了、换成 `Csr`。合入时若保留它，它就是一个潜在的 `unknown forwarder` 源。 **[S1]**（转发头归一到 `src/core/<layer>/` 属核心搬迁）

**③ master 的 perf 代码本身"不违规"（好消息，纠正一个常见猜测）**

把 master 的 `quadextractor.cpp/.h`、`singularitysimplifier.cpp/.h`、`quadparameterizer.cpp`、`positionkey.cpp/.h`、`autoremesher.h` 直接覆盖进 arch 的 `src/core/` 布局后：

**④ R5 的前提在 master 已经不存在了（必须换判据）**

文档 `:94` 写"`src/gui/**` 不得被 core / cli include"。master 的事实是：**GUI 是 `gui/` 下的 Go 代码，一行 C++ 都没有**；Qt 源码被整体删除（`21ad0f9c` "drop Qt, ship a headless CLI plus a Go GUI"）；arch 侧则是把 Qt 冻结到 `legacy/gui-qt/`。两种布局下 `src/gui/**` 这个路径都不存在。

所以 R5 要改成**构建图**上的约束，而不是 include 上的约束：

- 判据 1（CMake 侧，可机器判定）：任何 `add_library/add_executable` 的源列表与 `target_include_directories` 里，**不得出现 `legacy/gui-qt`、`gui/`、`ui-go/`**；等价地，`autoremesher_core` 的源集合只能来自 `cmake/core_sources.cmake` + 白名单第三方。

- 判据 3（残留检查）：Qt 头只需在 R1 里做，不需要 R5。

**判定顺序（G16，plan `:372`，不许跳步）**

1. 三份 sha **全等** → 逐字节等价，不用重跑基线，收工。
2. sha 变、但**拓扑四项**（`components` / `edges_non_manifold` / `boundary_loops` / `valence_histogram`）**全等** → 属"浮点累加顺序变化"，**可接受**，但**必须重跑基线并更新门表阈值**（阈值一律由基线推导，plan `:382`）。
3. 拓扑四项**也变** → 属**行为改变**，要按 D19 定位到具体动作（哪个 perf 提交/哪一步），不许直接放行。
