## 3. 三个决定性根因（带代码链）

### F1 落盘 OBJ 里的重复面

**现象链（逐位可复现）**

```
同一次运行（20k / adaptivity 0.3）：
  文件写出的面数            20,206
  去重后不同面              20,172   ← 差 34 份拷贝（26 组，其中 8 份反向绕序）
  按写入内容算边            boundary 5,  3 面边 104
  去掉重复面后算边          boundary 37, 3 面边 0
  Blender 4.x 导入同一文件   boundary 37, not_manifold 37, quads 19,663
```

Blender 的 OBJ 导入走 mesh.validate()，**静默丢弃重复多边形**，所以消费方量到 37/37；而 CLI 的 analyzeTopology（topologystats.cpp:140-148：count==1 记边界、count>2 记非流形）如实统计了**带重复面的文件**。两侧都没算错，是文件本身脏。

**跨 19 次运行都出现**：重复面 6–62 份（--legacy-holes 时翻倍到 46，--local-remesh 仍是 34）。也就是说它不来自某一次补洞，而是**所有拓扑清理 pass 的共同出口没有校验**：

- quadextractor.cpp:104-367 的 extract()：extractMesh(:225) → fixHoles(:229) → removeNonManifoldFaces(:257-266) → 再次 fixHoles(:270) → **然后还有 14 个 pass**（:294-328：splitSevenEdgeFaces … collapseThreeValenceEdgePairs）；
- 这 14 个 pass 每个都会重连面（合并共边五边形、翻转对角、合并 3/5 价位三角形…），**合并后可能正好等于一个已有面**，于是产生重复面；之后再没有任何 removeNonManifoldFaces() / removeDuplicateFaces()；
- quadextractor.cpp:2958 的 weldKeptPatches 注释自己写着「否则会出现被三个面共享的边」——同一个失效模式，只是发生在拼接阶段。

**修法（M0，最小改动）**：在 collapseThreeValenceEdgePairs()（:328）之后、report(1.0f, "")（:339）之前插一个 validateMesh()：按顶点集去重面（保留首次出现）→ 删重复索引/零面积面 → 再跑一次 removeNonManifoldFaces() 循环 → rebuildHalfEdges()；统计 duplicateFacesRemoved 进 ExtractionStats。

### F2 预算求解把整数结果当连续量

实测 trace（AR_TRACE_EXACT_TARGET=1）：

```
target=6000  adaptivity=0
  solved=0.00493729  base=0.00364025
  attempt=0 scale=0.0049373 uvArea= 9221.6  predicted= 8792.0 error=1.4653
  attempt=1 scale=0.0059743 uvArea=18509.9  predicted=17664.9 error=2.9441   ← 面积 ×2.0，s 只 ×1.21
  attempt=2 scale=0.0102443 uvArea=15369.6  predicted=14670.9 error=2.4452
  final ratio=2.5616                                                          → 实际 15,498 面
```

三个失效点，按贡献排序：

1. **模型假设**（quadparameterizer.cpp:760-795）假设 quads ∝ uvArea ∝ 1/s²。s 进的是 curl correction（:797-799）与 MILS 的固定行，整数取整后 uvArea 对 s 是**阶跃函数**，实测能反向跳。
2. **经验常数**（:910 extractionEfficiency = 0.955）是 body/head 上标定的；鞋上 attempt0 的 predicted/target = 1.465，说明常数偏了 46%。
3. **无发散守卫**（:893-930 最多 3 次 attempt）：误差 1.46 → 2.94 → 2.45，一次都没回到 1 附近，最后仍采用 attempt2 的 scale。

而 R5 的「−7.6% / −16.7%」只是这条链在另一档参数下的温和表现。

**修法**（见 §4 R5）：先加发散守卫 + 单调 bisection（廉价，直接消掉 +158%），再上「实测面数闭环」（准确，按需付时间）。

### F3 coresBusy 口径

autoremesher.cpp:1412-1423：m_coresBusy = Σ(resample + parameterize + extract 累计) / parallelWall。单岛时分子分母是同一个数 ⇒ 恒 1.00。R7 要求 coresBusy ≥ 4，在当前口径下**单壳模型永远 PASS 不了**。

**修法**：保留旧字段，新增 cpuBusy（进程 CPU 时间 / 墙钟，Windows 用 GetProcessTimes，Linux 用 clock_gettime(CLOCK_PROCESS_CPUTIME_ID)）与 threadsUsed（tbb::info::default_concurrency()）。R7 的验收改用 cpuBusy。

## 4. 逐项设计

> 每项：验收映射 → 现状 → 设计 → 落点 → 契约 → 测试 → 风险 → 人日。
> 原则：**新字段一律增量**（老的 quads/uvs/patches.kept 语义不动），算法改动一律带开关，默认关 → 验收通过后转默认。

### R1 --check-only

- **验收** 60k tri < 1.5 s 返回、不写文件、exit 0；输出与 result.topology.input 同构 + area/volume/bbox/unit_guess/boundary_loops/degenerate_edges/shell_count/advice。
- **现状** 未实现；但 analyzeInput()（autoremesher.h:297）与岛切分 MeshSeparator::splitToIslands（autoremesher.cpp:600）都是现成的，实测 analyze 150 ms + islands 46 ms。
- **设计**
  1. core 新增 InputCheck AutoRemesher::checkInput()：analyze → split islands → 统计；volume 走散度定理（闭合时非零；非闭合置 0 并给 volume_closed: false）。
  2. unit_guess 规则（写死、可解释）：bbox 对角线 d → d<1 → "m"；1≤d<100 → "cm"；d≥100 → "mm"，另给 unit_scale_to_mm（本用例 d=0.3113 → "m", 1000）。**不猜、不做启发式学习**。
  3. advice 规则表：
     - preset：二面角 > 40° 的边占比 > 5% → hard-surface，否则 organic；
     - weld_patches：shell_count > 1 → true；
     - projected_caps：存在 perimeter/medianEdge > 65 的边界环 → true；
     - expect_holes：boundary_loops > 0；
     - reason：上面每条命中的一句人话。
  4. CLI 在 main.cpp:1034 之后提前返回；-o 变为可选且不写盘，result.output 为 null。
- **契约** {"type":"result","checkOnly":true,"topology":{"input":{…}},"area":…,"volume":…,"bbox":{…},"unit_guess":"m","unit_scale_to_mm":1000,"boundary_loops":…,"degenerate_edges":…,"shell_count":…,"advice":{…}}
- **风险** 低（只读路径）。**人日 1.5**

### R4 退化单元清理

- **验收** 默认参数下 zero_length_edges = 0、quad_aspect_max ≤ --max-aspect（默认 20）。
- **现状** 落盘实测：零长边 1–8 条（六种配置里 4 种有），aspect 最大 **640,287**（6k/0.5），重复面 33；degenerateFaces: 0 只查了面。
- **设计** --clean-degenerate（默认 on）+ --max-aspect N（默认 20）：
  1. 零长边 → 合并两端顶点（不删面，避免造新洞）；
  2. 重复索引面 / 零面积面 → 删除，计入 cleaned_faces；
  3. aspect > N 的 quad → 沿最长边 collapse 一次（复用 collapseShortEdges 的邻接逻辑），失败则降级成三角形交给既有 cleanupTriangles；
  4. 结尾再跑一次 removeNonManifoldFaces()（与 M0 的 validateMesh 合并实现）。
- **注意** aspect 阈值过紧会伤网格：必须先 A/B（判据：quad_ratio 不降 1 pp、覆盖率不降、dev_p95 不涨 >2%），再定默认值。
- **落点** quadextractor.cpp:328 之后；计数进 ExtractionStats。
- **测试** gate R4 三条（dup=0 / zero_len=0 / aspect≤20）。
- **风险** 中（可能引入新洞）。**人日 2.0**

### R5 预算收敛

- **验收** 15 组矩阵 |error| ≤ 5%（target ≤ 6k 放宽 8%）。
- **现状** 5 组超差；最差 +158%（矩阵见 §9.1）。
- **设计** 三层，按成本递增，各自独立可关：
  1. **诚实汇报**（0.5d）：budget: {requested, islandTargets[], attempts, scalePerIsland[], predicted, actual, error, mode}；超差时发 warning target_quads_off（码已存在）。
  2. **发散守卫 + 单调 bisection**（1.0d）：把 :893-930 的定点迭代改成「记录 (s, predicted) 序列；误差连续两次朝错误方向走即回退到 argmin|error−1| 的尝试」；attempt 上限 4；extractionEfficiency 从常数改为 --extraction-efficiency（默认 0.955）并随规模微调。**这一步单独就能消掉 +158%**（回到 attempt0 的 8,792 附近）。
  3. **实测闭环**（1.0d）：--budget-retries N（默认 1）。抽取后拿每岛实际 quad 数，|error| > tol 时按 islandTarget *= target/actual 修正并**只重跑该岛**的 parameterize+extract。成本 +3–8 s/岛，因此必须与 R7 的并行收益一起评估；单岛输入上意味着整轮重跑，建议消费方对 6k 这类小目标开启、20k 保持默认 0。
- **落点** quadparameterizer.cpp:769-795（解析解与常数）、:883-930（尝试循环，插守卫与 bisection）；autoremesher.cpp:794-813（budget 分发，加实测修正）。
- **测试** gate R5（15 组）；另加「同参数两次运行 sha 一致」。
- **风险** 中：改 scale 会改所有输出，必须靠 docs/regression-anchors.json 的 sha 门 + A/B 脚本逐档验收。**人日 2.5**

### R6 对称三模式

- **验收** check 人工对称 >98%、非对称 <80% 且写 warning；snap |Δface| ≤0.5%；mirror-half 边界洞 = 0。
- **现状** 只有 mirrorSymmetrize（meshsymmetry.cpp:31），顺序是 **裁剪 → 吸附 → 焊接 → 镜像**（autoremesher.cpp:1269 调用），三者不可分离；--symmetry check 直接 exit 1（实测）。
- **复现事故**（本机，同契约参数 + --symmetry x）：clippedFaces 520, seamVertices 461, mirroredFaces 9171, vertices 20173→18257，deviation **mean 2.545 mm / p95 11.512 / max 23.422**（无对称时 0.100/0.297/2.447），与消费方 2.545/11.5/23.4 逐位一致。
- **设计** 把 mirrorSymmetrize 拆成三个独立函数 + 一个平面估计器：

| 新 API | 行为 | 必报字段 |
|---|---|---|
| evaluateSymmetry(v, f, axis, plane?) | 只测不改：KD/BVH 最近镜像点，match_pct（距离 ≤ tol 的顶点占比）、max_deviation、plane_estimate（未给平面时：顶点质量中心在该轴的投影中位数） | match_pct / max_deviation / plane_estimate |
| snapToPlane(v, f, axis, plane, tol) | 现有 :176-291 的吸附段独立出来，**不裁剪、不镜像** | snapped_verts / max_snap_mm |
| mirrorHalf(v, f, axis, plane, keepSide) | 现有 :86-173 裁剪 + :299-341 镜像 + 中缝焊接 | seam_verts / weld_failed / holes_after |

  CLI：--symmetry off|check|snap|mirror-half|x|y|z（x|y|z 保持旧语义 = mirror-half，正向）、--symmetry-keep positive|negative、--symmetry-plane auto|F。
  守卫：mirror-half 裁剪面 > 2% → warning symmetry_clip_heavy；check match < 80% → warning symmetry_mismatch（**只警告不阻断**，消费方要自己能决定）。
- **落点** meshsymmetry.h/.cpp（拆函数）、autoremesher.cpp:1268-1279（按模式分派）、main.cpp:360-372（参数解析）。
- **风险** 中（吸附段与裁剪共享状态，拆分要小心 UV 同步 :61-66）。**人日 3.0**

### R8 patches 语义

- **验收** 同输入 --weld-patches 下 remaining_shells ≤ 2，否则 reason 非空。
- **现状** PatchStats 只有 kept/dropped（autoremesher.h:56-59）；焊接阈值是量化位置键 voxelSize*1e-3（autoremesher.cpp:919）；实测 16 壳、输出顶点重合位置 **0 个** ⇒ 焊接确实生效，残留壳是「真缝隙/未补洞」，不是「没焊上的同位置点」。
- **设计** PatchStats 扩为 {kept, dropped, weldedVertices, remainingShells, minBoundaryGap, gapTolerance, reason}：
  - weldedVertices：weldKeptPatches（quadextractor.cpp:2958）返回的合并点数；
  - remainingShells：焊接后 analyzeTopology(...).components；
  - minBoundaryGap：跨壳最近边界顶点对距离（均匀网格哈希，O(n)），gapTolerance 为当前阈值；
  - reason 枚举："" | "no_weld_requested" | "open_holes" | "gap_exceeds_tolerance" | "overlapping_patches"，并在 reason == "gap_exceeds_tolerance" 时给 suggested_tolerance。
- **落点** quadextractor.cpp:2958（返回计数）、autoremesher.h:56-59、autoremesher.cpp:1291-1300（汇总）。
- **测试** gate R8（shells ≤ 2 或 reason 非空）。
- **风险** 低。**人日 2.0**

### R9 UV 可烘焙性

- **验收** 三种模式 uvs.area ∈ (0,1]；overlap_pct < 1 才允许 bakeable: true。
- **现状** uvs 是 bool（main.cpp:1142 只判 uvMode != "none"）。实测（target 8000 / adaptivity 0.3）：

| 模式 | UV 面积和 | 重叠格占比 | uvCorners |
|---|---|---|---|
| corner | 1.2255 | 67.5% | 29,718 |
| vertex | 11.1209 | 100% | 7,419 |
| hybrid | 1.4455 | 69.5% | 24,251 |
| seam | 1.4721 | 72.7% | 13,707 |

  四种模式**全部 >1**（= 重叠），与 help 里「corner 可烘焙」的暗示相反。根因：UV 只在 autoremesher.cpp:1158-1263 做条带排布 + 按 max(spanU,spanV) 整体归一，多 chart / 多岛互相重叠；角 UV 是单三角形仿射外推（uvtransfer.h:56-60），跨 chart 相邻面不拼接。
- **设计**
  1. **度量**（1.0d）：UVStats {area, overlap_pct, chart_count, max_stretch, bakeable}，挂 uvStats 对象。uvs（bool）**保持不变**以保护老读者 —— 需求方要的是对象，但那会破坏 v1 协议，建议 v2 再改语义，v1 先给 uvStats。overlap 用 512² 栅格（20k 面 ≈ 48 ms）+ 逐 chart 归属；chart_count 取 splitAtChartSeams 已有的 ChartSplit.chartCount。
  2. **布局修**（1.0d）：把「整网格按 max 跨度归一」改成 **shelf/box packing**：每 chart 一个 bbox → 按高度排序装箱 → 统一缩放填 [0,1]，留 0.5% 边距。这是唯一能让 area ∈ (0,1] 成立的改法。
- **落点** autoremesher.cpp:1079-1263（生成 + 排布）、main.cpp:582-712（写盘）、uvcharts.h（chart 数）。
- **测试** gate R9（area/overlap 双侧比对 + area∈(0,1] + bakeable 逻辑）。
- **风险** 中（改 UV 会改所有烘焙下游；必须 A/B「bake 一张 2048² 检查串图」）。**人日 2.0**

### R10 预设可扩展 + effective_params

- **验收** effective_params 与内部实际使用值逐项一致；同参数两次运行一致。

### R11 中断安全

- **验收** 取消后输出目录不出现残缺 obj；有 {"type":"abort"}、exit 130。
- **现状** fopen(path,"wb") 直写（main.cpp:576），无信号处理，exit code 只有 0/1/2/3。

### R12 尺度鲁棒性

- **验收** 同一模型缩放 0.1× / 1× / 10× 后，壳数、边界洞数**完全相同**，其余统计差 ≤2%。
- **现状** symmetry 容差已是 bbox 比例（meshsymmetry.cpp:57-58，好）；position weld 用 voxelSize*1e-3（autoremesher.cpp:919，相对「岛目标边长」，可接受但语义不同）；洞长阈值是**绝对边数** 8/65（quadextractor.cpp:1435-1447）；无 --unit-hint。
- **设计** 引入 ScaleContext { bboxDiagonal, targetEdge, unitScaleToMm } 贯穿到 extractor；把所有绝对量改比例：洞阈值 → holePerimeter / targetEdge（8/65 边 ≈ 默认值的等效换算，保持旧行为当 --legacy-hole-threshold）；--unit-hint mm|cm|m **只影响报告单位**（edge_len_mm、max_snap_mm），不改几何。
- **落点** quadextractor.cpp:114-117, 1435-1447；autoremesher.cpp:914-921。
- **测试** 新增 tools/capability_gate.py --rescale 0.1,1,10（缩放写临时 OBJ 再跑），判据见验收。
- **风险** 低-中。**人日 2.0**

### R7 单岛内并行度

- **验收** 60k tri / 20k target、8 核 wall ≤ 6 s，且 cpuBusy ≥ 4（口径见 F3）。
- **现状** 32 线程 16.63 s vs 8 线程 16.83 s（差 1.0%）—— 并行度只在岛这一层。鞋的阶段耗时：Isotropic 3.81 s / Parameterize 7.54 s / Extract 4.31 s / 固定串行 0.48 s；其中 **稀疏线性解 6.63 s（41.5%）**：Rounding cover 3.73（两次 attempt）+ Curl correction 1.75 + Eliminate constraints 0.93 + Cover system 0.22。
- **设计**（按「收益/风险」，每步可单独回滚）

| # | 动作 | 预计 | 风险 |
|---|---|---|---|
| 1 | cover attempt 收敛到 1（依赖 R5 的守卫与初值） | −1.8 s | 低 |
| 2 | isotropic Projecting vertices 并行（thirdparty，2.50 s 单线程） | −2.0 s | 中 |
| 3 | curl correction 复用分解/降规模 | −0.8~1.2 s | 中 |
| 4 | extraction per-face 段落并行（quadextractor.cpp:892 起，写冲突 + 编号不确定） | −1.5 s 上限 | 高 |
| 5 | 稀疏解换并行求解器（LDLT → 分块/迭代） | −4.5 s | 高 |

  Amdahl：串行下限 0.48 s；只做 1+2+3 ≈ 8.6 s（仍不达 6 s）；1+2+3 + 稀疏解 4× 并行 ≈ 3.6 s。**结论：6 s 目标绕不开第 5 项**，必须按「先低风险拿 1+2，再评估 5」的顺序立项。
- **落点** quadparameterizer.cpp:891-930、thirdparty/isotropicremesher、mixedintegerleastsquares.cpp:449-487、constrainedleastsquares.cpp:90-92。
- **附加** 并行化准入条件：① 结果与单线程逐字节一致（现有 anchor 门已有先例）；② Log::write（logging.h:71-75 无锁）在并行段内不许直接调用；③ 岛级 m_progressMutex（autoremesher.cpp:488）争用要复核。
- **风险** 高（改第三方 + 求解器）。**人日 8.0**

## 10. 给消费方的三条「现在就能用」的缓解

1. **R2 不必等**：tools/metrics/mesh_metrics.py measure out.obj 已经给出 poles_pct / valence_max / quad_aspect / zero_length_edges / components / boundary_loops，语义与本文 §4-R2 一致 —— 消费方可以立刻把它接进流水线做判据。
2. **重复面会在 Blender 侧被静默修掉**，所以「导入 Blender 后看着没问题」不代表产物干净；而且重复面把 32 条真实边界边藏了起来 —— 在 remove_doubles + fill_holes 之前先看 boundary_edges，否则补的是假洞。
3. **--symmetry 在非对称输入上不要开**；要检查对称度就先在 Blender 侧量匹配率（bmesh 最近镜像点），M2 会给出原生 --symmetry check。
